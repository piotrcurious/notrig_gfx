A better way to think about this is: graphics does not need trigonometry as its primary representation. It needs a representation of the rotation group and the projective group that is cheap to compose.

One important correction first: ordinary computers are not doing geometry in a Galois field. They usually use binary floating-point. Bitwise logic lives in GF(2), but your coordinates and transforms are almost never computed in a finite field. The real issue is that sin, cos, and atan2 are expensive transcendental evaluations, not the underlying binary arithmetic.

1) Replace angle-based rotation with algebraic rotation

For 2D, use the half-angle tangent parameter

t = \tan(\theta/2)

Then

R(\theta)=
\frac{1}{1+t^2}
\begin{bmatrix}
1-t^2 & -2t \\
2t & 1-t^2
\end{bmatrix}

This is already the key trick: no sin, no cos, only rational operations.

So rotating  becomes

x'=\frac{(1-t^2)x-2ty}{1+t^2},\qquad
y'=\frac{2tx+(1-t^2)y}{1+t^2}.

Example

Take . Then

1+t^2 = 1+\frac{4}{25} = \frac{29}{25}

and

R=
\frac{1}{29}
\begin{bmatrix}
21 & -20\\
20 & 21
\end{bmatrix}.

If , then

v' = \frac{1}{29}(21\cdot 3 -20\cdot 4,\;20\cdot 3 +21\cdot 4)
= \left(-\frac{17}{29},\frac{144}{29}\right).

That is exact, and it used only additions, multiplications, and one division by a rational number.

2) In 3D, use quaternions or Cayley transform

For general 3D rotations, the same idea extends cleanly.

Let  be a unit axis and . Define the skew matrix

[n]_\times=
\begin{bmatrix}
0 & -n_z & n_y\\
n_z & 0 & -n_x\\
-n_y & n_x & 0
\end{bmatrix}.

Then the rotation matrix can be written as the rational Cayley form

R = (I - t[n]_\times)^{-1}(I + t[n]_\times).

This avoids trig entirely. For implementation, quaternions are often even better:

q = \left(\frac{1-t^2}{1+t^2}, \frac{2t\,n_x}{1+t^2}, \frac{2t\,n_y}{1+t^2}, \frac{2t\,n_z}{1+t^2}\right).

Again: no sin, no cos. Just algebra.

3) Use projective geometry for projection

Perspective projection can also be handled without trig by using homogeneous coordinates.

A point  is multiplied by a  projection matrix, then divided by the resulting . That gives you the screen-space point. No transcendental functions are needed there either.

So the whole pipeline becomes:

orientation: quaternion or matrix multiplication,

rotation updates: Cayley / half-angle parameter,

projection: homogeneous matrix,

viewport mapping: affine transform.


4) Exact core, residual layer

Your idea about carrying residuals separately is good, but the clean way is usually a two-layer number system:

Exact algebraic core

Store what you can exactly in a number field such as

\mathbb{Q},\ \mathbb{Q}(\sqrt{d}),\ \mathbb{Q}(t),\ \mathbb{Q}(\sqrt{d_1},\sqrt{d_2},\dots)

This covers many useful angles and constructions exactly.

Residual carrier

For the part that cannot be represented exactly, keep a second component:

as an interval  for error bounds,

or as a dual number  for first-order residual propagation,

or as affine arithmetic if you want dependency tracking.


A practical representation is

x = x_{\text{exact}} + \delta

where  lives in the algebraic field and  is an error bound or residual term.

Strictly speaking, the residual layer is usually not a field. That is fine; it is the correct object for error tracking.

5) Very practical “rotate vector A onto vector B” formula

A lot of graphics code only needs “align this direction with that direction.” For that, there is an elegant trig-free formula.

For unit vectors  and , define

q = \text{normalize}\bigl(1 + a\cdot b,\; a\times b \bigr).

That quaternion rotates  to , except in the antiparallel case. It uses only dot, cross, normalization, and a square root.

This is often better than computing an angle at all.

Bottom line

If you want a trig-free graphics stack, the best approach is:

1. represent orientation by matrices or quaternions, not angles;


2. use Cayley / half-angle rational formulas for updates;


3. use homogeneous/projective coordinates for projection;


4. keep exact algebraic values in a field extension when possible;


5. keep unavoidable approximation in a separate residual layer.



So the replacement is not “finite-field trigonometry.” It is group-based geometry with algebraic parameterization, plus a separate error/residual channel.
